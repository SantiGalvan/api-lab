# Convertire le funzioni dichiarate in arrow function in tutto il codebase

## Contesto
Richiesta diretta dell'utente sullo stile: ogni dichiarazione/espressione `function` nei file `.js` del repo deve diventare una arrow function, dove possibile senza cambiare il comportamento. Nessun nuovo comportamento, nessuna decisione di dominio coinvolta — grilling/spec/ticket non si applicano qui (vedi `CLAUDE.md`, punto 2, step 1: "se non applicabile, dichiaralo esplicitamente").

## Tracking
Nessuno — richiesta di stile ad-hoc, non un ticket tracciato (vedi `docs/agents/issue-tracker.md`).

## Modifiche tecniche
```js
// core/auth/auth.js — i metodi di un oggetto letterale diventano proprietà
// con valore arrow; nessuno di essi usava `this`, quindi la conversione
// preserva il comportamento.
return {
  request: async (requestFn) => { /* ... */ },
  refresh: async () => { /* ... */ },
};
```

## Motivazione
Ogni funzione convertita è stata verificata per uso di `this`, ricorsione per nome, e sintassi generator (`function*`) — nessuno di questi pattern è presente nel codebase, quindi ogni conversione è meccanica e preserva il comportamento. I *getter* di oggetti letterali (`get baseUrl() { ... }` in `apps/mytask/config.js`) sono stati lasciati invariati: la sintassi accessor `get`/`set` non ha un equivalente in arrow function, quindi lì non c'era nulla da convertire. `HTTPError` è rimasta una `class` per lo stesso motivo — non è una funzione nel senso inteso da questa richiesta. Verificato con l'intera suite di test esistente (39 test, 7 file, tutti ancora verdi — nessun test è stato toccato nel comportamento, solo le due dichiarazioni `function` dentro `seedAndVerifyTask.test.js`) più `node --check` su `repl.js`/`scenario.js`, che la suite di test non importa direttamente.
