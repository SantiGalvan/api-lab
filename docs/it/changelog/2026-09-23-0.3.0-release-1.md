# MyTask: modalità login e switch di authMode per run

## Contesto
Ticket 3 della costruzione di api-lab, bloccato dal CRUD in m2m del Ticket 2. L'API reale di MyTask accetta anche un flusso `login`/password (come da ADR 0001), usato per simulare l'app reale come uno specifico utente invece di interrogare l'API con un token m2m fisso. Questo ticket collega questa seconda modalità ad `apps/mytask` end to end.

## Modifiche tecniche
```js
// apps/mytask/api.js — MyTask restituisce il token di sessione come header di
// risposta, non come campo del body, quindi authenticate() lo legge da lì.
async function authenticate(baseUrl, credentials) {
  const result = await post(buildUrl(baseUrl, 'authenticate'), { auth: credentials });
  const token = result.headers.get('token');
  if (!token) {
    throw new HTTPError(result.status, result.body);
  }
  return token;
}
```

```js
// core/auth/auth.js — refresh() permette a una funzione di dominio di forzare
// un login immediato (es. api.login(email, password)) invece di aspettare che
// scatti il percorso lazy alla prima richiesta/401.
async refresh() {
  cachedValue = await login();
  return cachedValue;
},
```

## Motivazione
`login()` riusa il meccanismo di lazy-login/refresh-su-401 già esistente in `createLoginAuthStrategy` (dal Ticket 1) invece di duplicarlo: si limita a sovrascrivere l'oggetto `credentials` condiviso e a chiamare il nuovo `refresh()` della strategia per forzare un login subito, così lo stesso token in cache serve sia la chiamata esplicita sia qualsiasi refresh automatico successivo. Esporre gli `headers` di risposta sul client condiviso (invece di una chiamata `fetch` ad hoc dentro `apps/mytask`) mantiene ogni funzione di dominio dentro `core/client`, e rende la stessa capacità disponibile a qualsiasi app futura la cui API restituisca token o metadati via header. `login()` lancia un errore in modo sincrono se chiamato fuori dalla modalità `login` invece di non fare nulla silenziosamente, perché un agente in modalità m2m che la chiama ha quasi certamente un'assunzione sbagliata sulla modalità di auth del run.
