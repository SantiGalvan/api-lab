# Convert standalone functions to arrow functions across the codebase

## Context
Direct style request from the user: every `function` declaration/expression in the repo's `.js` files should be an arrow function where that's possible without changing behavior. No new behavior, no domain decision involved — grilling/spec/tickets don't apply here (see `CLAUDE.md`, point 2, step 1: "if not applicable, state so explicitly").

## Tracking
None — ad-hoc style request, not a tracked ticket (see `docs/agents/issue-tracker.md`).

## Branch & Version
- **Branch:** `release/1`
- **Version:** `0.4.2`

## Technical changes
```js
// core/auth/auth.js — object-literal methods become arrow-valued properties;
// none of them used `this`, so the conversion is behavior-preserving.
return {
  request: async (requestFn) => { /* ... */ },
  refresh: async () => { /* ... */ },
};
```

## Rationale
Every converted function was checked for `this` usage, recursion by name, and generator syntax (`function*`) — none of these patterns appeared anywhere in the codebase, so every conversion is mechanical and behavior-preserving. Object-literal *getters* (`get baseUrl() { ... }` in `apps/mytask/config.js`) were left untouched: `get`/`set` accessor syntax has no arrow-function equivalent, so there was nothing to convert there. `HTTPError` was left as a `class` for the same reason — it's not a function in the sense this request meant. Verified with the full existing test suite (39 tests, 7 files, all still green — no test was touched for behavior, only the two `function` declarations inside `seedAndVerifyTask.test.js`) plus `node --check` on `repl.js`/`scenario.js`, which the test suite doesn't import directly.
