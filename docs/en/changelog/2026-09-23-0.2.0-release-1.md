# App mytask: config + Task CRUD in m2m mode + REPL

## Context
Ticket 2 of the api-lab build-out, blocked by Ticket 1's shared engine. The first real app: a developer can open a REPL on `mytask` and do real CRUD on the Task resource as plain JS objects, authenticating with a pre-provisioned m2m token (per ADR 0001).

## Technical changes
```js
// apps/mytask/api.js — every domain function is a thin composition of the
// shared engine's HTTP verb + the app's auth strategy; no fetch call is made
// outside core/client.
function getTask(id) {
  return strategy.request((token) => get(buildUrl(env.baseUrl, `tasks/${id}`), { token }));
}
```

```js
// repl.js — generic across future apps: it never hardcodes "mytask", it only
// assumes each app's config.js/api.js default-exports getEnvironment/makeApi.
const { default: getEnvironment } = await import(`./apps/${appName}/config.js`);
const { default: makeApi } = await import(`./apps/${appName}/api.js`);
```

## Rationale
`config.js` exposes environment fields as getters over `process.env` rather than a plain object literal, so tests can stub env vars per-case without fighting ESM module caching. `makeMytaskApi`'s `options.authMode` defaults to `'m2m'` and throws for anything else — `login` mode exists as a concept in ADR 0001 but this app doesn't have login credentials wired up yet, so failing loudly beats silently misbehaving. `repl.js` resolves the app/env pair through a `default`-export convention on `config.js`/`api.js` instead of hardcoding `mytask`, so the next app only needs to follow the same shape to get a REPL for free.
